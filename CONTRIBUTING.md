# Contributing

This repository is primarily a portfolio and learning project, but it follows a professional workflow.

1. Link work to a backlog ID.
2. Create a focused branch from `main`.
3. Keep credentials and generated service keys outside Git.
4. Add or update tests with behavioral changes.
5. Update architecture documents when boundaries or integrations change.
6. Use a conventional commit message and keep the pull request demonstrable.

Before merging, verify that documentation links resolve, relevant tests pass, no secrets are present, and screenshots do not expose account identifiers or credentials.
